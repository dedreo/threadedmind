yea, on that note, would I be just transitioning between frames, or would I use gifs that are animated? I'm guessing the latter?

Assistant
Great question—and yeah, you’ve got a couple solid options depending on how you’re building the game and how flexible you want to be later.

### ⚙️ If you’re coding with a game framework (like Phaser, Pygame, or anything similar):
You’ll typically **transition between frames using a sprite sheet** (an image with each frame of animation in a row/column). You define animations in your code, and the game just swaps which "frame" is visible on each tick.

This method is:
- **Lightweight** (since it loads one image and cycles through it)
- **Flexible** (you can tweak timing, reverse animations, change frames mid-action, etc.)
- **Most common** in 2D game development

### 🖼️ If you use animated GIFs:
You could technically use GIFs, but...
- They’re **less flexible**—harder to control speed or sync with gameplay
- You can’t easily change or interrupt the animation mid-way (like squish a blob mid-jump)
- Some engines don’t support them natively for animated sprites

### 🧊 TL;DR:
You’ll want to **create your blobs with frame-by-frame animations** (like 3-5 frames of squish, scooch, bounce, etc.), export them as **sprite sheets or individual frames**, and use the engine's animation system to play them.
