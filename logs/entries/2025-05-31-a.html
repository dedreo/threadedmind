​
Deploying Your React App to GitHub Pages — Step-by-Step Guide
​
## Prerequisites
- A React project created with `create-react-app` or similar.
- A **GitHub account**.
- Your React project is in a GitHub repository. (If not, instructions below to set it up.)
​
---
​
## Step 1: Create a GitHub Repository (if you haven’t yet)
​
1. Go to [github.com](https://github.com) and log in.
2. Click the **"+"** icon (top right) → **New repository**.
3. Enter a repository name (e.g., `my-react-app`).
4. Select **Public** repository.
5. Click **Create repository**.
6. If your project is local, initialize git and push it:
​
```bash
cd path/to/your/react-project
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/your-username/your-repo-name.git
git push -u origin main
```
​
---
​
## Step 2: Add the `homepage` Field in `package.json`
​
Open your `package.json` and add:
​
```json
"homepage": "https://your-username.github.io/your-repo-name"
```
​
Replace `your-username` and `your-repo-name` with your GitHub username and repository name.
​
Example:
​
```json
{
"name": "my-react-app",
"version": "0.1.0",
"private": true,
"homepage": "https://johndoe.github.io/my-react-app",
...
}
```
​
---
​
## Step 3: Install `gh-pages`
​
In your project directory, run:
​
```bash
npm install gh-pages --save-dev
```
​
---
​
## Step 4: Add Deployment Scripts
​
In `package.json` under `"scripts"`, add:
​
```json
"predeploy": "npm run build",
"deploy": "gh-pages -d build"
```
​
Example:
​
```json
"scripts": {
"start": "react-scripts start",
"build": "react-scripts build",
"test": "react-scripts test",
"eject": "react-scripts eject",
"predeploy": "npm run build",
"deploy": "gh-pages -d build"
}
```
​
---
​
## Step 5: Deploy Your App
​
Run the deploy command:
​
```bash
npm run deploy
```
​
This will build your app and push the `build` folder to a `gh-pages` branch on GitHub.
​
---
​
## Step 6: Verify GitHub Pages Settings
​
1. Go to your GitHub repository page.
2. Click **Settings** → **Pages**.
3. Ensure the source is set to the `gh-pages` branch and folder `/root`.
4. Note the URL where your site is published:
​
```
https://your-username.github.io/your-repo-name/
```
​
---
​
## Step 7: Visit Your Deployed Site!
​
Open the URL above in your browser. Your React app should be live!
​
---
​
## Troubleshooting Tips
​
- GitHub Pages works on **public repositories** for free accounts.
- After any changes, run `npm run deploy` again to update.
- If using React Router, configure `basename` in your router for GitHub Pages routing.
​
---
​
## Quick Checklist
​
- [ ] GitHub repo created and linked.
- [ ] `homepage` added to `package.json`.
- [ ] Installed `gh-pages`.
- [ ] Added deployment scripts.
- [ ] Ran `npm run deploy`.
- [ ] Verified GitHub Pages settings.
- [ ] Visited live URL.

Assistant
Yep—classic `CRLF` vs `LF` line ending warning. Not an error, just git being a little verbose about platform differences. Here's what's going on:

---

### ⚙️ What it Means:
- `CRLF` = Carriage Return + Line Feed (Windows default line endings)
- `LF` = Line Feed (Unix/macOS/Linux standard, and preferred by most repos)

Git is telling you:
> “Hey, I noticed your files use Windows-style line endings (`CRLF`), but the repo is set to use Unix-style (`LF`). Next time I rewrite these files (like during a commit or checkout), I’ll switch them to `LF`.”

---

### ✅ Should You Worry?
**Nope.** This is totally normal and safe to ignore **unless**:
- You're working on a team with strict formatting rules (you're not).
- Some files are behaving weird due to line endings (not likely in a React app).

---

### 💡 If You Want to Silence the Warning:

You can explicitly tell Git to auto-convert line endings for you:

```bash
git config core.autocrlf true
```

This tells Git:
- On **commit**: Convert `CRLF` to `LF`
- On **checkout** (on Windows): Convert back to `CRLF` so your editor doesn’t freak out

Or if you want Git to **leave line endings alone**, use:

```bash
git config core.autocrlf false
```

---

### Summary:
- ✅ The warning is safe to ignore.
- ✅ Git is helping keep your repo consistent.
- ❌ It won’t break your deploy or commit.

Carry on with `git commit -m "Initial commit"` — you're fine.
